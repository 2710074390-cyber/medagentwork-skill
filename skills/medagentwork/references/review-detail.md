# 复习资料详细度契约（HC-26）

> 本文改编自原项目 `docs/复习资料详细度标准.md`（v1.0.0 · 2026-10-27 · 主责 Agent 5）。
> `{SKILL}` = 本 skill 安装目录；命令须在用户工作区执行。
> 单一事实来源：`{SKILL}/scripts/quality_policy.json` 的 `review_detail_*` 阈值。
> 机械门禁：`{SKILL}/scripts/check_review_detail.py` · 契约 Schema：`{SKILL}/schemas/review_detail.schema.json`。
> 适用范围：所有**新生成/重新生成**的教师重点版、教学计划版、课程安排版复习资料。旧产物**不追溯、不回改**。

---

## 0. 一句话结论

**详细度不是字数，而是「读一遍后能否独立完成临床推理与应试判断」。**

一份合格的详细复习资料，必须让读者在不另开教材的情况下，对每个掌握级考点回答九个问题：
**是什么 → 为什么 → 怎么认 → 怎么查 → 怎么治 → 和谁鉴别 → 哪里易错 → 怎么记 → 能否回忆**；
掌握级还要能完成一次**病例迁移**（案例）。

---

## 1. 证据基础：为什么这样定

| 证据 | 结论 | 转成的契约 |
|---|---|---|
| 引导式笔记（guided notes）元分析：大学阶段效果量约 0.4–0.5；医学课程中结构化教师笔记显著提高期末成绩 | 「有结构、有检索点」的讲义优于纯听讲，也优于无结构全文 | 九槽位固定结构 + 每卡自测 |
| 完整讲义 vs 骨架讲义研究：完整讲义会减少学生自己的加工，部分内容保持下降 | 详细 ≠ 全文转录 | 槽位完整 + 反注水 + 自测 |
| 检索练习 + 分散练习系统综述（健康职业教育） | 每卡必须有可检索问题，答案可查 | `🔄 自测` + 附录 100% 覆盖 |
| 认知负荷理论 / worked examples / self-explanation | 掌握级需完整推理链与案例；熟悉/了解级降低要求；超长要拆分 | 三级槽位表 + 字符上限 + `🔬 展开` |
| 疾病脚本（illness script）理论 | 按疾病脚本组织，而不是按教材目录罗列 | `🧬 机制` + `👁 识别` + `⚖️ 鉴别` 固定顺序 |
| 细化追问（elaborative interrogation） | 每个掌握级考点必须解释「为什么」 | `🧬 机制` 强制，含「如果…就不会…」 |
| 教学大纲「掌握/熟悉/了解」三级要求 | 详细度必须按层级分层，不能一刀切 | 掌握 9 槽位+案例；熟悉 7；了解 4 |

> 字符下限是**项目基线校准值**，应在每 2 个批次后用实际学习结果复校，不要当成「字数科学」。

## 2. 三种输入模式

| 模式 | 触发 | 组织单位 |
|---|---|---|
| `teacher_keypoint` | 提供 `输入素材/{科目}/{科目}_教师重点_<学校或日期>.md`，或 MD 中出现 `📌 重点原文（第X条）` | 教师重点条号 + 模块/卡片 |
| `course_schedule` | 提供课程安排文件，或 MD 中出现 ≥2 个 `## 第N周/第N讲/Week N/Lecture N` 标题 | 周 / 讲 / 课时 |
| `module` | 既无教师重点锚点、也无周讲结构，仅有 `## 模块N` | 模块 / 卡片 |

- **教师重点模式**：教师重点仍是**范围契约（下限）**——逐条覆盖、原文锚定、数值零改写（HC-20 不变）。顺序是：**先逐条覆盖 → 再按九槽位展开 → 最后自测**，不得用概括替代原文。
- **课程安排模式**：每一讲回答「学什么（目标）→ 带着什么来（课前）→ 讲什么（重点）→ 为什么（机制）→ 怎么用（案例）→ 怎么考（映射）→ 会不会（自测）→ 花多久/接哪里（时间与衔接）」。若同时有教师重点，每讲还要标覆盖的条号。
- **模块模式**：卡片按九槽位分级要求，模块按八块要求；不强制教师重点锚点，但必须保留教材页码。

## 3. 卡片级契约：九问 + 案例

### 3.1 九个槽位（槽位标签强制）

| # | 读者问题 | 槽位标签 | 最低内容要求 |
|---|---|---|---|
| 1 | 是什么/在哪 | `<b>🎯 定位</b>` | 一句话题眼 + 定义/解剖位置/分类归属 |
| 2 | 为什么会这样 | `<b>🧬 机制</b>` | 正常→触发→病理→表现的因果链；至少 1 个「如果…就不会…」转折 |
| 3 | 怎么认出来 | `<b>👁 识别</b>` | 典型场景 + 核心症状 + 关键体征 + 关键阴性 |
| 4 | 怎么查/怎么确诊 | `<b>🔍 诊断</b>` | 首选检查 + 确诊金标准 + 分级/分期界值 + 何时做鉴别性检查 |
| 5 | 怎么治/怎么处理 | `<b>🩺 处置</b>` | 治疗原则 + 一线方案 + 禁忌/转诊/随访 |
| 6 | 和谁混/怎么分 | `<b>⚖️ 鉴别</b>` | ≥3 行对比表，≥2 个鉴别对象；每行给可判定差异 |
| 7 | 哪里最容易错 | `<b>🚨 易错</b>` | 1–2 个真实错误 + 为什么错 + 正确口径 |
| 8 | 怎么记住 | `<b>🧠 记忆钩子</b>` | 一句话/口诀/对比锚；不得是标题复述 |
| 9 | 能否回忆 | `<b>🔄 自测</b>` | 2–3 个原子问题；答案必须进附录 |
| 10 | 能否迁移（仅掌握级） | `<b>🏥 案例</b>` | 3–5 行病例 → 关键发现 → 最可能诊断 → 下一步 |

> 兼容：旧版 `🎯 一句话题眼` 可保留但必须并入 `🎯 定位`；旧版 `🩺 下一步` 视为 `🩺 处置` 的兼容写法。

### 3.2 分级要求与量化阈值

「正文」= 去掉空白、`📌 重点原文` 锚点行与 HTML 标记后的字符数。
「信息单元」= 可判定句子/条目 + 表格数据行 + 图块；用于防止用空话凑字数。

| 层级 | 必填槽位 | 正文字符下限（pilot / release） | 信息单元下限（pilot / release） | 字符上限 |
|---|---|---:|---:|---:|
| 🔴 掌握 | 九槽位全部 + 案例 | 700 / 900 | 9 / 12 | 3600 / 3200 |
| 🟡 熟悉 | 定位、机制、识别、诊断、处置、鉴别、自测 | 450 / 550 | 6 / 7 | 2600 / 2400 |
| 🟢 了解 | 定位、识别、鉴别、自测 | 220 / 250 | 3 / 4 | 1800 / 1600 |

> 900 字符 ≈ 九个槽位各 100 字符 + 一张 3 行鉴别表 + 一个短案例，是**最低可读单位**，不是「越长越好」。

### 3.3 掌握级卡片模板（生成时逐行照此结构）

```markdown
#### 🔴 K-Mxx-xxx｜{考点名}（教师重点第X条｜P##）

📌 重点原文（第X条）：{照录原文关键句；数值/时间窗/并列/禁止结构一字不改}

<b>🎯 定位</b>：{一句话题眼}；{定义/解剖位置/分类归属}
<b>🧬 机制</b>：{正常→触发→病理→表现}；{如果…就不会…}
<b>👁 识别</b>：{典型场景}；{核心症状}；{关键体征}；{关键阴性}
<b>🔍 诊断</b>：{首选检查}；{确诊金标准}；{分级/分期界值}；{何时加鉴别检查}
<b>🩺 处置</b>：{治疗原则}；{一线方案}；{禁忌/转诊/随访}
<b>⚖️ 鉴别</b>：

| 鉴别轴 | 本病 | 鉴别病A | 鉴别病B |
|---|---|---|---|
| 起病/病程 | … | … | … |
| 关键体征 | … | … | … |
| 首选检查 | … | … | … |

<b>🚨 易错</b>：{错误1}；{为什么错}；{正确口径}
<b>🧠 记忆钩子</b>：{一句话/口诀/对比锚}
<b>🏥 案例</b>：{年龄/诱因/主诉/关键查体或检查} → {最可能诊断} → {下一步}
<b>🔄 自测</b>：{问题1}；{问题2}（答案见附录）
```

熟悉级去掉 `🏥 案例`，其余七个槽位保留；了解级只保留定位、识别、鉴别、自测。

### 3.4 反注水规则（与下限同等重要）

1. 每句话必须提供**事实、机制、决策规则或鉴别点**之一；禁止同义反复、空泛评价、把标题改写成句子。
2. 禁止「详见教材/略/众所周知」；禁止只写「首选 X」而不写「为什么首选、何时不选」。
3. 一个槽位只讲一个主题；超过字符上限时拆 `#### 🔬 展开：…` 或独立卡片，不得堆成整页墙。
4. 表格优先于长段罗列；因果链优先于重复叙述；同一事实不得在多个槽位重复计入。
5. 自测必须**原子化**：一题一个事实/决策，答案可检索。
6. 详细度以「读者能否复述/判断」为准，能用 900 字说清就不写 1800 字。

## 4. 模块级契约：八块齐全

| 块 | 判定 | 最低要求 |
|---|---|---|
| 前置知识 | `🧩 前置知识检查` | 3–5 个问题，指向本模块先修概念 |
| 模块摘要/目标 | `🎯 30 秒摘要` 或 `学习目标` | 5 条以内，覆盖必考点 |
| 对比表 | 标准 Markdown 表 | ≥3 行数据 |
| 因果链 | `🔗 因果链` 或含箭头的代码块 | 5–15 节点 |
| 案例推演 | `🏥 案例推演` | ≥1 例；含关键发现、最可能诊断、下一步、易错分支 |
| 主动回忆 | `🔄 自测` / `🔄 主动回忆` | ≥1 组；答案可检索 |
| 本章小结 | `📌 本章小结` | 3–5 条 take-home message |
| 展开区 | `#### 🔬 展开：` | ≥2 个/模块 |

另：每模块 callout ≥4；模块信息框含权重、题型、谱系位置、预计阅读时间。

```markdown
### 🏥 案例推演：{主诉}

{3–5 行：年龄/诱因/主诉/关键查体/关键检查}

| 步骤 | 判断 |
|---|---|
| 关键发现 | … |
| 最可能诊断 | … |
| 下一步 | … |
| 易错分支 | … |
```

## 5. 课程安排版契约：每讲八块

| 块 | 判定 | 最低要求 |
|---|---|---|
| 学习目标 | `🎯 学习目标` | 掌握/熟悉/了解三级各 ≥1 条，用可测量动词 |
| 课前准备 | `🧩 课前准备` / `前置知识` | ≥2 条，指明先修与预习任务 |
| 课堂重点 | `📚 课堂重点` | ≥3 条，按课时分节；每条含机制或判断规则 |
| 机制解释 | `🧬 机制` / `原理` | ≥1 条完整因果链 |
| 案例 | `🏥 案例` / `病例` | ≥1 例，含下一步 |
| 课后自测 | `🔄 自测` / `课后任务` | ≥2 问，答案可检索 |
| 时间预算 | `⏱ 时间预算` / `学时` | 写明学时或分钟分配 |
| 前后衔接 | `⏭️ 下周衔接` / `关联` | 说明本讲在课程中的位置 |

量化：每讲正文 ≥1000（pilot）/ ≥1200（教师重点版）/ ≥1400（教学计划版）；信息单元 ≥10 / 12 / 14。
若同时有教师重点，每讲增加 `🔍 考点映射`，列本讲覆盖的条号、题型、分值。

## 6. 判定与门禁

### 6.1 命令

```bash
# 教师重点版 / 常规模块版
python {SKILL}/scripts/check_review_detail.py \
  --md "复习资料/{科目}教师重点版/{科目}教师重点版_主复习资料.md" \
  --mode auto --profile release_teacher_keypoint \
  --json-out reports/validate/review_detail_{科目}.json \
  --md-out reports/validate/review_detail_{科目}.md

# 教学计划版
python {SKILL}/scripts/check_review_detail.py --md <教学计划版 MD> --mode module --profile release_teaching_plan

# 课程安排版
python {SKILL}/scripts/check_review_detail.py --md <课程安排版 MD> --mode course_schedule --profile release_teaching_plan
```

退出码：`0` PASS/WARN；`1` FAIL（enforce 下阻断，必须返工）；`2` 输入错误。
`--advisory` 把 FAIL 降级为 WARN，**不得用于正式发布**。

### 6.2 通过条件（release）

| 指标 | 通过线 |
|---|---:|
| 掌握级槽位完整率 | 100% |
| 卡片达标率（槽位+字数+单元） | ≥90%（教师重点版）/ ≥95%（教学计划版） |
| 自测答案覆盖 | 100% |
| 模块八块完整率 | 100% |
| 模块案例覆盖 | 100% |
| 详细度总分 | ≥90%（教师重点版）/ ≥92%（教学计划版） |

`pilot` 档位放宽为：核心槽位 ≥85%、卡片达标 ≥75%、自测答案 ≥95%、模块块 ≥85%、案例模块 ≥85%、总分 ≥80%。

> **自测答案覆盖依赖附录对账**：`check_review_detail.py` 通过 `spaced_schedule.py` 解析卡片自测题与附录答案行并做配对。附录缺失或题号对不上，自测槽位一律判缺失——这不是脚本 bug。

### 6.3 交付形态：单一文件

模块可以分批、分片生成，但**交付物只能是一份合并后的 MD**：

- `M01.md … Mnn.md` 只允许留在 `中间产物/{batchID}/`，不得进入交付目录。
- 附录（页码索引/术语对照/来源锚点/自测答案）必须随合并写回；只合模块正文、丢附录视为不合格。
- 详细度门禁与导出兼容自检（V14）**只对合并后的文件运行**；分片上的 PASS 不构成交付通过。

## 7. 与既有规则的关系

| 规则 | 关系 |
|---|---|
| HC-20 教师重点锚定 | HC-26 不替代 HC-20；先逐条覆盖原文，再展开九槽位 |
| HC-18 产物形态 | `check_review_detail.py` 只查结构，不查导出兼容；V14 仍须单独跑 |
| HC-24 题目学习价值 | 题目层与文档层分开：HC-24 管题，HC-26 管复习资料 |
| HC-25 阶段门禁 | `review_detail` 接入 R2/R3；R3 enforce FAIL 阻断发布 |
| 展开区 / callout | 保留；模块八块已包含展开区 ≥2、callout ≥4 |
